# RC Planner 2.0 — аудит и переосмысление дизайна

Дата: 2026-09-01. Ветка: `claude/project-design-rethink-1bc7b7`.
Канвас с направлениями и экранами: https://claude.ai/code/artifact/d514007c-a206-46f3-b2dc-a826a7b7c28d
(исходники — `docs/design/`, см. README там).

## Коротко

- Приложение 1.5 концептуально цельное: цикл «флот → чек-лист → полёт →
  журнал → обслуживание» замкнут, приватность — свойство конструкции,
  пять наборов тестов зелёные. Переписывать нечего — перестраивать надо
  **структуру и состояния**, а не стиль.
- Главные разрывы: «Сегодня» не знает, где пилот (дома / на поле /
  после полётов); одно действие «начать полёт» имеет четыре названия;
  «Журнал» и «Статистика» спрятаны на два касания, а «Сборы» занимают
  вкладку; у локального приложения нет напоминания о резервной копии;
  анимаций нет вовсе; на десктопе — колонка 640 px в пустоте.
- Предложены три направления (А «Пульт» — ведущее, Б «Бортжурнал»,
  В «Панель»), для А нарисованы все состояния дня и система токенов,
  движения и технологий. **Направление выбирает владелец** — до этого
  код приложения не перестраивается (глобальное правило «план → согласие
  → работа»).
- В этой сессии в коде исправлена только гигиена: кириллица в `app.js`
  была записана `\uXXXX`-последовательностями (7 строк), версия
  в `package.json` отставала (1.0.0 → 1.5.0). Сборка и все тесты зелёные.

### 2.2 Анимации

Сейчас: поворот шеврона `details.fold` (150 мс) и `:active` прозрачность.
Всё остальное — мгновенно, включая модальные листы и смену экранов.
Причина техническая: `render()` пересобирает `#views` целиком, CSS-переходы
на замещённых узлах невозможны. Решение — **View Transitions API** (same-document):
`document.startViewTransition(() => render())` анимирует именно замену
innerHTML, без изменений архитектуры. Спецификация движения — артборд
«Система» на канвасе (что, длительность, механизм, fallback). Правила:
одна кривая `cubic-bezier(.2,.8,.2,1)`, длительности 80/140/180/220 мс,
всё гаснет при `prefers-reduced-motion` (медиа-запрос уже есть в CSS).

### 2.3 Технологии (без зависимостей, всё — прогрессивное улучшение)

| Что | Зачем | Fallback |
|-----|-------|----------|
| View Transitions API | переходы экранов и точечные обновления `render(true)` | как сейчас, мгновенно |
| `@starting-style`, `transition-behavior: allow-discrete` | вход/выход `dialog` и `::backdrop` без JS | появляется сразу |
| `popover` | меню «⋯», выбор состояния пункта чек-листа, сортировка — вместо модалок | модалка |
| Container queries | рельса + две колонки от 900 px | одна колонка |
| CSS nesting, `:has()`, `color-mix()`, `oklch()` | короче стили; тона статусов из одного цвета вместо 12 rgba-констант | — |
| Wake Lock API | экран не гаснет, пока идёт полёт (индикатор на экране полёта) | индикатор прячется |
| Web Share API (files) | резервная копия через системный лист «Поделиться» на iPhone: Файлы, AirDrop — вместо неловкой загрузки в standalone-PWA | обычный `download` |
| `content-visibility: auto` | каталог инструментов и журнал рисуются лениво | — |
| `field-sizing: content` | textarea растёт по тексту | фиксированная высота |
| `structuredClone` | копия пресета вместо `JSON.parse(JSON.stringify())` | — |

Перед кодом каждой из них — сверка через Context7/MDN (малознакомые
браузерные API при первом использовании — правило проекта) и живая проба
в Safari на iPhone: именно там живёт PWA владельца.

Что **не** предлагается: ES-модули и сборщики (ломают однофайловую
сборку `dist/`), фреймворки, web-шрифты по сети (запрет офлайн-правила;
встроенный шрифт — только если выбрано направление Б, +~120 КБ).

### 2.5 Приватность (обязательный угол)

Редизайн не добавляет сетевых точек: View Transitions, `popover`,
Wake Lock, container queries — локальные API. Web Share отдаёт файл копии
системному листу — получателя выбирает пользователь, приложение ничего
не отправляет само (описать на странице «Приватность»). Метка «есть новее»
у версии прошивки компонента берётся из ручного списка `data/firmware.js`,
без запросов. Напоминание о копии считается из локальной даты последнего
экспорта. Скриншоты для канваса сняты на посеянных вымышленных данных.

## 4. Структура направления А

- Вкладки: **Сегодня · Флот · Полёт · Журнал · Ещё**. «Сборы» —
  карточка «Перед выездом» на «Сегодня» (пока есть несобранные пункты)
  и пункт в «Ещё».
- «Сегодня» — четыре состояния, одна главная кнопка на экран:
  1. *дома* — окна на сегодня для основной локации (полоска дня),
     «Перед выездом» (сборы, АКБ на зарядку), «К вылету», напоминание о копии;
  2. *на поле* — подготовленный борт как герой с «Взлёт», полоска
     условий, «Ещё к вылету», обслуживание;
  3. *в полёте* — живой таймер в карточке, точка на вкладке «Полёт»;
  4. *разбор* — итоги дня, «Разобраться» (проблемный полёт → осмотр,
     АКБ после полёта → зарядить, N полётов без копии → сохранить).
- Борт: герой (статус, АКБ-пилюля, три числа, регламент-полоска, одна
  кнопка «Чек-лист и полёт»), сегменты «Обзор · Компоненты · Обслуживание
  · История»; пустые компоненты спрятаны за «+ Добавить»; у компонента
  поле версии прошивки (задел под firmware-журнал из ROADMAP).
- Чек-лист: пилюли локации/АКБ, прогресс, тап по строке — «ок», тап по
  клетке — поповер «Ок / Проблема / Пропустить»; внизу липкая пара
  «Начать полёт» + «Готов».
- Полёт: кольцо относительно обычной длительности борта, контекст
  пилюлями, «Посадка» 64 px, индикатор «экран не гаснет».
- Окна: пилюли борта/места, чипы дней с точкой-вердиктом, полоска 24 ч
  с выбранным часом и его карточкой, список «обратить внимание».
- Журнал: сегмент «Полёты | Статистика», фильтры-пилюли, меню «⋯»
  (печать, CSV).
- Десктоп ≥ 900 px: рельса вкладок 88 px, колонка 720, правая колонка
  360 (условия, полёты дня, копия).
- Заделы под ROADMAP: «Помощник · online» в «Ещё» с тем же паттерном
  согласия, что у погоды; строка «Копия N дней назад» — место для
  будущей синхронизации через файл.

## 5. План внедрения (после выбора направления)

Схема версий проекта: `X.0` — крупный выпуск. Всё это — **2.0**, но
в четыре выкладки, каждая — сборка, тесты, code-review с углом
приватности, запись в changelog, обновление `VIEWS` в `test/audit.js`.

1. **2.0 «Каркас»** — вкладка «Журнал» (маршруты `#/log`, `#/stats`
   под ней), «Сборы» на «Сегодня» и в «Ещё»; «Сегодня» по состояниям;
   единое имя действия («Начать полёт», «Взлёт», «Посадка»);
   напоминание о копии (`settings.lastBackupAt`, порог 14 дней);
   метка online → `--info`; View Transitions для `go()` и `render(true)`;
   вход/выход `dialog` через `@starting-style`; SVG вместо текстовых знаков.
2. **2.1 «Борт и чек-лист»** — герой и сегменты карточки, скрытые
   пустые компоненты, поле версии прошивки; поповер состояния пункта;
   липкая пара кнопок; кольцо и Wake Lock на экране полёта.
3. **2.2 «Окна и журнал»** — полоска дня и чипы дней; фильтры и меню
   журнала; подписи месяцев «сентябрь 2026».
4. **2.3 «Верстак»** — container queries, рельса и две колонки;
   Web Share для копии; `content-visibility` для каталога и журнала.

Проверка: к пяти наборам добавить снимки с посеянными данными
как шестой набор `test:seeded` (сделано в пакете 6: `test/seeded.js`,
бывший `docs/design/shots.js`) — сравнение глазами до/после каждой
выкладки; XSS-пробы и аудит экранов остаются.
