# RC Planner 3.0 — ТЗ на фон и картинки

Документ для исполнителя (в том числе ИИ-агента), который делает **только
графику**. Код, стили и сборку не трогаем — места под картинки в приложении
уже заложены, сборка подхватит файлы сама.

## 0. Границы задачи — прочитать первым

- Создавать и менять **только файлы в `assets/art/`** с именами из
  `assets/art/slots.json`. Других файлов не трогать: ни `src/`, ни `styles/`,
  ни `index.html`, ни `public/`, ни `dist/`, ни `package.json`,
  ни `AGENTS.md`, ни `slots.json`.
- `npm run build` и `npm test` не запускать и их результат не коммитить —
  сборку сделает основной агент (и CI при выкладке на Pages).
- Проверка — одна команда: `npm ci && npm run art:check`. Всё зелёное —
  готово. Красное — исправить файл, а не проверку.
- Коммит — только `assets/art/*.webp` и `assets/art/*.svg`,
  сообщение вида «Картинки: фон, заглушки бортов, приветствие».
- Не нужно делать все 17 слотов разом: любой файл необязателен.
  Без файла приложение показывает запасной вид (процедурный фон, иконку).
  Порядок важности: фоны → заглушки бортов → пустые состояния → приветствие.

## 1. Правила безопасности и лицензий

Приложение офлайн и приватное (правило проекта). Поэтому:

- никаких внешних ссылок и ресурсов внутри файлов (в SVG — ни `href` на
  сеть, ни `<image>`, ни `url(http…)`, ни скриптов, ни `on…=`);
- никакого текста, букв, цифр, логотипов, брендов, водяных знаков,
  людей и узнаваемых мест (координаты, вывески, номера);
- только сгенерированная или собственная графика — без чужих фото,
  стоков и скриншотов;
- метаданные (EXIF, XMP, геометки) в файлах не оставлять — при
  перекодировании через sharp они удаляются по умолчанию.

## 2. Дизайн-система «Кокпит»

Настроение: приборная панель пилота в сумерках — тёмный графит с холодным
синим подтоном, чистые тонкие линии, мягкое свечение «приборного» циана.
Сдержанно и технично, без мультяшности и без «кислотного» неона.

Палитра (значения из `styles/00-tokens.css`):

| Роль | Тёмная тема | Светлая тема |
|------|-------------|--------------|
| Фон (основа) | `#0b1017` (в «Максимуме» `#070b12`) | `#eef2f7` |
| Поверхность карточки | `#151d28` | `#ffffff` |
| Поверхность 2 | `#1c2633` | `#f2f5f9` |
| Линии | `#283444` | `#d8dfe8` |
| Текст | `#eaf0f7` | `#0f1722` |
| Акцент (циан) | `#3fd6f0` | `#067591` |
| Акцент 2 (сине-фиолетовый) | `#7c8cff` | `#4c5bd4` |
| «Можно / готов» (зелёный) | `#3ddc84` | `#0c7a40` |
| «На пределе» (янтарь) | `#f3c24b` | `#7a5a00` |
| «Не стоит / запрет» (красный) | `#ff5a5f` | `#b3262d` |

Мотивы (любые сочетания, но спокойно):

- топографические изолинии рельефа — «лётное поле», место полётов;
- тонкая приборная сетка, дуги радара, штрихи шкал по краям;
- пунктирная траектория полёта, еле заметная;
- мягкие светящиеся пятна акцента (циан сверху-слева, фиолетовый
  снизу-справа), как подсветка приборов.

Стиль отрисовки: плоские тона и мягкие градиенты, линии 1–2 px на
итоговом размере, без фотореализма в фонах, без шума и зерна
(плохо жмутся и мешают тексту).

## 3. Как картинки используются (важно для композиции)

- **Фон** лежит под всем интерфейсом, растянут `cover` по центру и
  закреплён (не прокручивается). Режимы: «Стандарт» — прозрачность 55 %,
  «Максимум» — 100 % и поверх него стеклянные полупрозрачные карточки,
  «В перчатках» — фона нет. Поверх фона — шапка экрана (верхние ~15 %),
  столбец карточек по центру, плавающая панель вкладок внизу (~10 %).
- Отсюда: **центр — самый спокойный и тёмный** (светлый — в светлой теме),
  детали и свечение — к краям и в верхнюю треть. Текст на карточках
  должен читаться без усилий.
- **Заглушка борта** — квадрат со скруглёнными углами 52–76 px на экране
  (превью 512×512 уменьшается в 7–10 раз), лежит на плашке `#1c2633`
  в тёмной теме и `#f2f5f9` в светлой. Должна читаться мелко: один
  силуэт, крупная форма, без мелочи.
- **Приветствие** — картинка над заголовком шага в окне шириной до 380 px.
- **Пустые состояния** — SVG используется как **маска**: цвет берёт
  приложение (градиент циан → фиолетовый). Значит, важны только форма
  и прозрачность — цвет штриха в файле роли не играет.

## 4. Слоты — точные требования

Имена, размеры и лимиты — ровно как в `assets/art/slots.json`
(проверяет `npm run art:check`). Растр — только **WebP**, sRGB.

### 4.1 Фоны (WebP, без прозрачности)

| Файл | Размер | Лимит | Где |
|------|--------|-------|-----|
| `bg-dark.webp` | 1290×2796 | 220 КБ | тёмная тема, телефон |
| `bg-dark-wide.webp` | 2560×1600 | 300 КБ | тёмная тема, от 900 px |
| `bg-light.webp` | 1290×2796 | 220 КБ | светлая тема, телефон |
| `bg-light-wide.webp` | 2560×1600 | 300 КБ | светлая тема, от 900 px |

- Тёмные: основа `#070b12`–`#0f1724`, средняя яркость картинки не выше
  ~12 %; яркие только небольшие пятна свечения у краёв.
- Светлые: основа `#eef2f7`–`#f7f9fc`, линии `#c9d6e6`, лёгкие тона
  циана и фиолетового; средняя яркость не ниже ~88 %.
- Пара «телефон / широкий» — одна сцена, перекомпонованная под формат.
- Пример запроса генератору (тёмный, телефон): *«Vertical 1290×2796 abstract
  background, deep navy-graphite #0b1017, faint topographic contour lines
  and a subtle HUD grid fading toward the center, thin radar arcs near the
  top-left corner, soft cyan #3fd6f0 glow top-left and soft indigo #7c8cff
  glow bottom-right, very calm dark center area for UI cards, flat vector
  style, no text, no noise, no people»*.

### 4.2 Заглушки бортов без фото (WebP с прозрачностью, 512×512, до 80 КБ)

`type-quad.webp` (FPV-квадрокоптер, вид 3/4 сверху, четыре пропеллера),
`type-plane.webp` (самолёт-модель, вид 3/4), `type-wing.webp` (летающее
крыло), `type-other.webp` (нейтрально: пропеллер или абстрактный борт).

- Силуэт занимает ~70 % холста по центру, прозрачный фон.
- Корпус — графитовые тона `#3a4658`–`#5b6b82`, акцентные огни и кромки —
  циан `#3fd6f0`, немного зелёного `#3ddc84`; мягкая тень под объектом.
- Одинаковый ракурс, свет и масштаб у всех четырёх — это один набор.
- Проверить глазами на обоих фонах плашки: `#1c2633` и `#f2f5f9`.

### 4.3 Приветствие (WebP с прозрачностью, 720×480, до 110 КБ)

- `welcome-1.webp` — «Что это»: приборная панель-телефон, над ней силуэты
  квадрокоптера и самолёта, линии данных.
- `welcome-2.webp` — «Как устроен день»: дуга из пяти светящихся узлов —
  рюкзак → чек-лист → взлёт → посадка → журнал, узлы соединены пунктиром
  траектории.
- `welcome-3.webp` — «Приватность»: щит с замком над устройством, данные
  остаются внутри (линии замыкаются в контур), без облаков и сети.
- Один стиль на все три; прозрачный фон; окно бывает тёмным и светлым —
  не использовать чисто белые и чисто чёрные крупные заливки.

### 4.4 Пустые состояния (SVG-маска, до 12 КБ)

`empty-fleet.svg` (ангар с квадрокоптером), `empty-journal.svg` (раскрытый
бортжурнал и пунктир траектории), `empty-batteries.svg` (аккумулятор со
знаком заряда), `empty-sites.svg` (метка места на изолиниях),
`empty-packing.svg` (рюкзак с галочкой), `empty-generic.svg` (бумажный
самолётик над пунктиром).

- Корень: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 240 160">`.
- Только контуры: `fill="none" stroke="#000" stroke-width="2"
  stroke-linecap="round" stroke-linejoin="round"`; допускаются мелкие
  заливки-точки.
- **Строгий белый список** (`art-rules.js`; сборка ПАДАЕТ на нарушении —
  открытый по прямой ссылке SVG выполнялся бы на адресе приложения):
  - элементы: `svg g path rect circle ellipse line polyline polygon defs
    linearGradient radialGradient stop clipPath mask`;
  - атрибуты: геометрия (`d x y x1 y1 x2 y2 cx cy r rx ry points width
    height transform viewBox`), оформление (`fill stroke stroke-* opacity
    fill-* clip-rule vector-effect`), `id`, `xmlns` (только SVG),
    `clip-path`/`mask`/`fill` со ссылкой вида `url(#id)`;
  - нельзя: `<title>`, `<desc>`, `<text>`, `<style>`, `<image>`, `<a>`,
    `<use>`, `<script>`, фильтры `<fe…>`, анимации, атрибуты `style`
    и `class`, префиксы пространств имён (`xlink:`, `sodipodi:`,
    `inkscape:`), сущности `&…;`, обратный слэш, текст вне тегов.
    Экспорт из редакторов обычно содержит лишнее — чистить руками или
    писать SVG кодом.
- Стиль — как иконки приложения (Lucide-подобный контур): простые
  геометричные линии, 15–40 путей, воздух по краям 10–15 px.

## 5. Как получить WebP нужного размера

`sharp` уже есть в devDependencies (`npm ci`). Пример перекодирования
исходника любого формата в слот:

```js
// node scripts-tmp/encode.js — временный скрипт, в репозиторий не коммитить
const sharp = require('sharp');
sharp('source.png')
  .resize(1290, 2796, { fit: 'cover' })   // размер слота
  .webp({ quality: 78, alphaQuality: 90, effort: 6 })
  .toFile('assets/art/bg-dark.webp');
```

Не влезает в лимит — снизить `quality` (до ~60) или упростить детали;
разрешение не менять.

## 6. Проверка и сдача

1. `npm ci && npm run art:check` — все строки с ✓.
2. Глазами: фоны — центр спокойный; заглушки — читаются мелко на тёмной
   и светлой плашке; SVG — открыть в браузере, контуры ровные.
3. Коммит только файлов `assets/art/*` в ветку задачи.

Что происходит дальше (делать не нужно): сборка находит файлы, вставляет
для них правила стиля, кладёт в `public/art/` и в прекэш офлайн-режима;
офлайн-файл `dist/rc-planner.html` остаётся без картинок (он один
и без соседних файлов).
