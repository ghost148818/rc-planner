# RC Planner 2.0 — спецификация реализации (направление А «Пульт»)

Решения владельца (2026-09-01): направление А; вкладка «Сборы» уходит
с панели, но чек-лист сборов остаётся; тема по умолчанию — по системе;
Web Share для резервной копии; режим «в перчатках» в настройках;
анимации нужны. Ветка станет основной; 1.5 остаётся резервной веткой.

Это техническое задание для реализации. Контекст и мотивация — в
`docs/redesign-2.0.md`, картинки — на канвасе (ссылка там же). Правила
проекта — `CLAUDE.md` (обязательны: `esc()` для любого пользовательского
текста, `numVal()` для чисел в `value=`, SVG только через `ICONS[key]`,
никаких сетевых ресурсов в сборке, online только по явному действию).

## 0. Общие правила для всех пакетов

- Один файл `app.js`, разделы пронумерованы — новое кладём в свой раздел,
  не в конец файла. Стили — `styles.css`, только vanilla CSS.
- Не ломать инварианты: `takeoffReady()` — единственный источник кнопки
  «Взлёт»; `statusOf()` и цепочка «проблема → осмотр → Готов»;
  `installBattery()`/`battLockedBy()`; `prepared` гаснет в `takeoff()`;
  одно модальное окно; `dismissModal()`/`UI.modalReturn`.
- Каждый новый экран — в `RENDERERS`, `TAB_OF`, и в `VIEWS`
  `test/audit.js`; экраны с аргументом (`#/model/<id>`) в VIEWS не идут.
- После правок: `node build.js` и `npm test` (пять наборов; шестой —
  `test:seeded` — добавляется в пакете 6). Правка без сборки в тесты не
  попадает.
- Тексты только по-русски; «модель» в интерфейсе — «Борт» (мужской род:
  «Готов», «подготовлен», «собран»). Никаких эмодзи; текстовые знаки
  ✓ ✕ — ★ ☆ × заменяются SVG из `ICONS`.
- localStorage — только UI-предпочтения: `rcp.theme` (`light`|`dark`;
  отсутствует = по системе), `rcp.gloves` (`1`), `rcp.hi`, `rcp.seen`,
  `rcp.seeded`, `rcp.tour`. Всё остальное — IndexedDB.
- Никаких новых сетевых точек. Web Share — системный лист, приложение
  ничего не отправляет само. Wake Lock, View Transitions, popover —
  локальные API. Каждая — прогрессивное улучшение с проверкой наличия.
- Версия для changelog — `'2.0'`, одна запись на всё (сборка ещё не
  отдана). Пункты — до 160 символов, записей в списке не больше 12.

## 1. Пакет «Фундамент»: тема, перчатки, токены, движение

### 1.1 Тема по системе
- `index.html`: убрать `data-theme="dark"` с `<html>`. Инлайн-скрипт
  в `<head>` до первой отрисовки: `t = localStorage.rcp.theme`; если
  `light`/`dark` — ставим `data-theme=t`; иначе — по
  `matchMedia('(prefers-color-scheme: light)')` ставим `light` или `dark`.
  Тот же расчёт вынести в `app.js` как `applyTheme()`; подписка на
  `matchMedia(...).addEventListener('change')` перечитывает, если
  предпочтение не задано. CSS не меняется: светлые токены остаются под
  `:root[data-theme="light"]`.
- `<meta name="theme-color">` обновлять из `applyTheme()` под фактическую
  тему: тёмная `#14181e`, светлая `#f2f3f5`.
- Настройки («Ещё»): сегмент из трёх — «Как в системе · Тёмная · Светлая»
  (`data-act="theme-set" data-theme="system|dark|light"`); `system`
  удаляет ключ `rcp.theme`.
- `pwa/manifest.json`: `background_color`/`theme_color` не трогать
  (тёмные — заставка при запуске).

### 1.2 Режим «В перчатках»
- `rcp.gloves = '1'` → инлайн-скрипт и `applyTheme()` ставят
  `<html data-gloves>`.
- CSS переводится на переменные размеров в `:root`:
  `--tap: 48px; --row: 56px; --btn: 48px; --primary: 56px; --seg: 40px;
  --font: 16px; --font-d: 13px; --ck-box: 44px; --tab-h: 60px`.
  Под `:root[data-gloves]`: `--tap: 56px; --row: 64px; --btn: 56px;
  --primary: 64px; --seg: 48px; --font: 17px; --font-d: 14px;
  --ck-box: 52px; --tab-h: 68px`. Все правила `.row`, `.btn`, `.btn-primary`,
  `.btn-sm` (min-height `--seg`), `.seg button`, `.ck`, `.ck .st`,
  `.tab`, `input/select/textarea` читают переменные.
- Настройки: под темой сегмент «Обычный · В перчатках» с подписью
  «Крупнее кнопки и строки — для поля». `data-act="gloves-set"`.
- Отступ `#views` снизу и `.tabbar` считать от `--tab-h`.

### 1.3 Токены и мелочи
- `.badge.online`: цвет `--info` (синий), не `--warn`.
- `STATUS.ready.label` → `'Готов'`. Проверить все тексты, где статус
  согласован по роду («Готова» встречается в `data/changelog.js` — старые
  записи не трогать).
- Подписи месяцев в статистике: `'сен 2026'` (`MONTHS_RU[m] + ' ' + year`).
- Текстовые знаки → SVG: `ICONS.check`, `ICONS.x`, `ICONS.minus`,
  `ICONS.star`, `ICONS.starOff`, `ICONS.close` (крестик), `ICONS.plus`.
  Контуры — стиль существующих (штрих 1.8–2.2, 24×24). Использовать
  в `.ck .st`, `.dlg-close`, избранном инструментов, «+ Группа».
- `textarea { field-sizing: content; min-height: 84px }`.
- `.fold .fold-body { content-visibility: auto; contain-intrinsic-size:
  auto 400px }` для каталога инструментов и истории.

### 1.4 Движение (View Transitions и CSS)
- В разделе 9 (навигация): `UI.navDir` — `'forward'|'back'|'tab'`.
  `go()` ставит `forward`; `nav-back` и `popstate`/`hashchange`, если
  новый маршрут — предыдущий (хранить короткий стек `UI.navStack`) —
  `back`; переход между корневыми экранами вкладок — `tab`.
- `render(keepScroll)`: если есть `document.startViewTransition` и нет
  `prefers-reduced-motion`, то `document.documentElement.dataset.vt =
  keepScroll ? 'update' : UI.navDir` и
  `document.startViewTransition(() => paint())`; иначе `paint()` напрямую.
  `paint()` — нынешнее тело `render`. Живой таймер и восстановление
  фокуса/прокрутки — внутри `paint()`.
- CSS: `::view-transition-old(root)`/`::view-transition-new(root)`:
  `html[data-vt="forward"]` — новый въезжает на 24 px и проявляется
  180 мс, старый гаснет 140 мс; `back` — зеркально; `tab` — только
  прозрачность 140 мс; `update` — `animation: none` у root (ничего не
  моргает), анимируются только элементы с `view-transition-name`:
  клетки чек-листа `.ck .st` получают `style="view-transition-name: ck-<i>"`
  (масштаб .9 → 1, 200 мс через `::view-transition-new(ck-*)`; имена
  уникальны в пределах страницы). Кривая везде
  `cubic-bezier(.2,.8,.2,1)`.
- `dialog`: `@starting-style { transform: translateY(24px); opacity: 0 }`,
  `transition: transform .22s, opacity .22s, overlay .22s allow-discrete,
  display .22s allow-discrete`; `::backdrop` — прозрачность.
  Закрытие: `closeModal(immediate)` — при анимациях добавляет класс
  `closing` (уезжает вниз 160 мс) и удаляет узел по `transitionend` либо
  через 200 мс; `openModal` вызывает `closeModal(true)` (мгновенно, чтобы
  не жить двум окнам). `body.locked` снимать сразу.
- `.btn:active { transform: scale(.98) }` с `transition: transform .08s`
  вместо прозрачности; `.progress i`, `.bar-track i`, `.gauge i` —
  `transition: width .24s`.
- Таймер: `<span class="colon">:</span>` мигает 1 с (`@keyframes`), число
  после посадки — цвет `--mut`.
- `@media (prefers-reduced-motion: reduce)` уже гасит всё — оставить.

  `'field'` — есть борт с `takeoffReady()`; `'debrief'` — есть
  завершённые полёты за `todayISO()`; иначе `'home'`.

  подпись «собран»); АКБ с `charge === 'flown'` — строка «Зарядить: …»
  с чипом-действием `batt-charge`; борта с подошедшим регламентом
  (`svcState().due`) — строка «Пора осмотреть» с кнопкой «Осмотр».
  (3) «К вылету»: `armedFleet()` со статусом, кнопка «Чек-лист» у
  готовых. (4) Открытое обслуживание (как сейчас). (5) Баннер копии
  (3.2). Главная кнопка «Начать полёт» — над «К вылету», если есть
  собранные борта.
- **field**: герой — борт с `takeoffReady()` (последний по
  `prepared.at`): крупный thumb, имя, АКБ, «Чек-лист пройден в HH:MM ·

  (`takeoff-prepared`). Ниже — компактная полоска погоды из кэша (если
  свежая), «Остальные борта» (другие собранные: «Чек-лист» / статус),
  «Обслуживание» (due + открытые).
- **flying**: герой — карточка полёта с живым `#timer` (интервал в
  `paint()` обновляет `#timer`, если он есть на любом экране, по активной

  Ниже — как в field без героя взлёта.
- **debrief**: плитки «полётов сегодня · налёт · с проблемой»; блок
  «Разобраться»: полёты за сегодня с `result` не `normal`, у борта
  которых нет закрытой работы новее полёта — строка с кнопкой «Осмотр»

  «Осмотр после полёта #N»); АКБ `flown` — «Зарядить N аккумуляторов»
  (перечислить, чип `batt-charge` на каждой строке или одна кнопка
  «Все заряжены» — `batts-charged-all`); «Сохранить резервную копию»
  с подписью «N полётов с последней копии» (3.2); «Проверить, что всё
  собрано» → `#/packing` (если есть наборы). Далее «Полёты сегодня»
  (`logGroupedHtml` за день) и кнопка «Ещё один полёт» (`start-prep`).
- Прежние блоки «Последние полёты» и строка «Окна» в «Ещё» — убрать
  (окна остаются на «Сегодня» во всех состояниях: герой или строка).

### 3.2 Резервная копия: дата и напоминание
- `S.settings.lastBackupAt` (мс) ставится после успешного `export-all`
  (после `download()` или успешного `navigator.share`).
- `backupDue()`: `true`, если есть данные (борта или полёты) и
  `lastBackupAt` пуст либо старше 14 дней. На «Сегодня» (home/field) —
  баннер «Резервная копия — N дней назад» / «Резервной копии ещё не было»
  с кнопкой «Сохранить» (`export-all`). В debrief — строка с числом полётов
  после `lastBackupAt`.
- Экран «Данные»: подпись «Последняя копия: дата» / «ещё не было».

### 3.3 Web Share
- `saveFile(name, blob)` в разделе 2 (утилиты): если
  `navigator.canShare && navigator.canShare({ files: [file] })` —
  `await navigator.share({ files: [file], title: name })`; `AbortError`
  (пользователь закрыл лист) — тихо; любая другая ошибка — `download()`.
  Иначе — `download()`. `exportData` и `csvSave` используют `saveFile`.
  Возвращает `true`, если файл ушёл (для `lastBackupAt`).
- Страница «Приватность»: пункт «Резервная копия и CSV на телефоне
  предлагаются через системный лист «Поделиться»: куда положить файл,
  решаете вы; приложение само никуда его не отправляет».

## 4. Пакет «Борт, чек-лист, полёт»

### 4.1 Карточка борта (`viewModel`)
- Герой-карточка: `aircraftThumb` крупный (72 px), имя в шапке, чип
  статуса + маленький селект «авто/вручную» (как сейчас, но компактнее:

  - Обзор: паспорт (сетка 2 колонки: вес сухой/взлётный, размах,

### 4.2 Чек-лист (`viewPrep`, шаг 2)
- Верх: селекты локации и АКБ как пилюли `.sel-pill` в один ряд
  (`overflow-x: auto`, без обрезания названия внутри пилюли — ширина

- Прогресс: полоска + «N / M» моноширинно; подсказка «тап по строке — ок,
  по клетке — выбор» под полоской.
- Состояния: тап по строке (`ck-toggle`) — переключает `ok` ↔ пусто;
