# Работа над RC Planner

Локальное офлайн-приложение авиамоделиста: флот, чек-листы, полёты,
обслуживание, конфигурации. Без сервера, аккаунтов, аналитики и внешних
запросов. Vanilla HTML/CSS/JS, никаких зависимостей в рантайме.

Папка проекта: `~/projects/rc_planner`. Публикация: GitVerse Pages из `public/`.
Референс продуктовой философии — `~/projects/put-rebenka` (код и дизайн не копируем).
Планы и принципы продукта — `ROADMAP.md`; описание для пользователя — `README.md`.

## Цикл выпуска

```bash
npm run icons     # только если менялся assets/icons/app-icon.svg
npm run build     # public/ (PWA) + dist/rc-planner.html (офлайн-файл)
npm test          # пять наборов подряд, останавливается на первом упавшем
```

Порядок важен: `npm test` ничего не собирает. `test:audit` и `test:single`
читают `dist/rc-planner.html`, `test:pwa` и `test:visual` — папку `public/`.
Правка в `app.js` без `npm run build` не попадёт в проверяемую сборку.
`npm run release` делает всё по порядку.

Один набор — `npm run test:data|audit|single|pwa|visual` (`test:data` — единственный
без браузера). Скриншоты visual-набора падают в `test/shots/`. Свежая машина:
`npm run setup` (ставит зависимости и chromium для Playwright), нужен Node ≥ 20.

Если изменение видно пользователю — новая запись в начало `data/changelog.js`
со своим `v` — **строкой** (`'0.9'`, `'1.0'`): версии уникальны, порядок задаётся
положением в списке, арифметики на `v` быть не должно (`'0.10' < '0.9'` как
строки). Первая запись показывается как «версия» в футере «Ещё». Просмотренную
версию `maybeWhatsNew` ищет по совпадению в списке: незнакомое значение (старый
формат, копия из будущего) — показать окно один раз. Без записи окно «Что нового»
не всплывёт. Записей держим не больше двенадцати, пункты — до 160 символов.
**Одна выкладка — одна запись:** пока сборка не отдана пользователям,
дописываем в верхнюю запись, а не заводим новую.

## Как устроено приложение

**`app.js`** — один файл, двенадцать пронумерованных разделов: состояние,
утилиты, статусы, данные, примитивы, экраны, действия, формы, навигация,
события, PWA, старт.

**Экраны.** Экран — функция `view*()`, возвращающая строку HTML; карта
`RENDERERS` (id → функция), `TAB_OF` привязывает экран к вкладке нижней панели.
`render()` целиком заменяет `#views`; `render(true)` сохраняет прокрутку и фокус
(нужно для отметок в длинных списках). Переходы — `go(hash)`, маршруты вида
`#/model/<id>`. Новый экран — запись в `RENDERERS`, `TAB_OF` и в список `VIEWS`
в `test/audit.js`, иначе его никто не проверит.

**События.** Обработчиков на элементах нет: разметка пересобирается целиком,
поэтому `click`/`submit`/`change` висят на `document`, элементы помечены
`data-nav`, `data-act`, `data-form`, `data-change`. Действия — в `ACTIONS`,
формы — в `FORMS`.

**Данные.** Пользовательские данные — IndexedDB через `db.js` (обёртка без
зависимостей); снимок целиком живёт в `S`, после записи store перечитывается.
Blob (фото, файлы конфигураций) хранятся прямо в IndexedDB; в экспорт уходят
как base64 (`__blob`). Новые store добавлять в `STORES` в `db.js` (+ миграция
по версии) и в snapshot/экспорт ничего — он универсальный. localStorage —
только тема, приветствие, `rcp.seen`, `rcp.seeded`; основной базой не является.

**Справочный контент** (не пользовательские данные) — `data/*.js`:
чек-листы, каталог инструментов, стартовые сборы, changelog. Чтобы поправить
текст, трогать код не нужно. Инварианты данных стережёт `test/checks.js` —
самый быстрый набор, браузер ему не нужен.

**Экранирование.** Весь пользовательский текст в HTML — только через `esc()`.
Аудит гоняет XSS-пробу; новую вставку без `esc()` он поймает не всегда —
следить руками.

**Сборка.** `build.js` вклеивает CSS, `db.js`, `data/*.js` и `app.js` в HTML
по маркерам `<!-- build:… -->` и делает два выхода: `public/` с manifest, sw
и иконками и `dist/rc-planner.html` без PWA (по `file://` service worker
не работает; регистрация SW в рантайме дополнительно ограждена протоколом).
Версия — sha1 сборки; подставляется в `sw.js` и `<meta name="build">`, откуда
её показывают настройки. Сборка падает при внешних ресурсах, битом manifest
и иконках старше SVG.

## Правила, за которые уже заплачено (наследие референса)

- **Обновления.** Навигация в SW — из сети, кэш запасной; регистрация
  с `updateViaCache: 'none'`. В `install` **нет** `skipWaiting()`: управление
  передаётся только по кнопке «Обновить». `controllerchange` перезагружает
  страницу лишь когда контроллер уже был — при первой установке событие
  тоже приходит.
- **Окна.** Одно модальное окно за раз (`openModal` сам закрывает прежнее).
  Не полагаться на `::backdrop` — блокировка фона своя (`body.locked`).
  Закрытие по кнопке, Esc и фону идёт через `dismissModal()`: он возвращает
  прерванную форму из `UI.modalReturn` (сценарий «+ Добавить локацию» из итога
  полёта). Внутри `openModal` остаётся именно `closeModal()` — иначе рекурсия.
  Стэш хранит значения через `FormData`, поэтому не годится для форм с файлами
  (фото модели).
- **Иконки.** Все SVG лежат в `ICONS` и вставляются ТОЛЬКО как `ICONS[key]`
  (третий аргумент `rowBtn` — ключ, не разметка). Пользовательские строки
  в SVG-слоты не попадают; аудит такую ошибку не поймает.
- **Имена файлов — латиницей**: macOS хранит имена в разложенной форме Unicode,
  после распаковки git видит «двойники».
- **Не подключать CDN, шрифты и картинки по сети** — приложение обязано
  работать офлайн; сборка это проверяет. Это про ресурсы самого приложения:
  online-API (погода) допустимы, но только по явному действию пользователя,
  с пометкой «online», честным сообщением офлайн и записью в CSP `connect-src`.
- **Ссылки наружу** (каталог инструментов) — только официальные источники,
  `target="_blank" rel="noopener noreferrer"`, пометка «online». Чужие прошивки
  не распространяем — только ссылки на релизы производителей.
- **Вертолёты не планируются** — решение владельца.

## Context7 — когда обязателен, а когда не нужен

Решение владельца (2026-08-23, уточнено 2026-08-24): Context7 используется
всегда, когда код опирается на внешнее знание, и НЕ используется там,
где он бесполезен, — лишние запросы тоже ошибка.

**Обязателен перед кодом, который трогает:**

- внешние API и сервисы (Open-Meteo и т.п.) — параметры и лимиты сверить
  через Context7 **и** подтвердить живым запросом (`curl`), потому что
  документация и реальность могут расходиться;
- API библиотек и dev-инструментов (sharp, playwright и любые новые);
- малознакомые браузерные API при первом использовании в проекте;
- ссылки каталога `data/tools.js` — сверка с официальной документацией.

**Не нужен (не тратить запросы):**

- собственная логика приложения: экраны, расчёты, `esc()`, роутинг;
- вёрстка HTML/CSS, тексты, changelog, правки данных в `data/*.js`;
- проверка живости ссылок — это curl/WebFetch, Context7 этого не умеет.

**Проверка ссылок** (всегда, Context7 тут только для сверки с доками):
HTTP 200 + заголовок/содержимое страницы соответствуют назначению
(`curl … | grep -i "<title>"` или WebFetch) + ресурс известен сообществу.
Урок 2026-08-24: adamone.rchomepage.com отдавал 200, но вёл на вредоносную
страницу — код ответа ничего не гарантирует. Дату последней проверки
обновлять в шапке `data/tools.js`. Ссылку, которую невозможно проверить
из текущей сети (гос-сайты), не добавлять самому — предложить владельцу
проверить и добавить после его подтверждения.

Если Context7 недоступен — сказать прямо и пометить непроверенное.

## Окна для полётов: как считаются пороги

Логика (решение владельца, 2026-08-24): **модель → место → дата → окна**.
Ограничения выводятся из ТТХ модели, а не берутся константой:

- порог ветра — `a.maxWind`, а без него оценка `wxEstimate()` по типу
  и весу (в интерфейсе помечается «≈»); шкала рассчитана на опытных пилотов
  (базы 16–20 м/с, решение владельца 2026-08-24; сохранённые пороги моделей
  удвоены разовой миграцией `migrateIfNeeded`);
- высота полёта — `a.maxAlt` (потолок поля — 200 м); 200 м — это высота
  полёта, а не «проверять ветер всегда до 200 м»: уровни ветра Open-Meteo
  (80/120/180 м) берутся только в пределах высоты полёта модели
  (`wxLevels()`), низколетящий квад не бракуется ветром на 180 м;
- порывы — до 1.4 порога, осадки ≥0.2 мм или вероятность ≥60 % — «bad»;
- окна считаются только в светлое время (sunrise–sunset);
- прогноз — ориентир, решение о вылете всегда за пилотом (дисклеймер
  в интерфейсе не убирать);
- индекс дня привязывается к датам из ответа API, не к «сегодня + N»,
  иначе вчерашний кэш сдвигает дни.

Менять пороги и эвристики — только в разделе «Окна для полётов» в `app.js`,
они собраны там в одном месте (`wxEstimate`, `wxLevels`, `wxVerdict`).

## Чего не делать

- Не тащить зависимости в рантайм (`sharp` и `playwright` — только dev).
- Не заводить серверную БД, аккаунты и обязательную синхронизацию.
- Не переписывать проект целиком ради стиля — менять минимально необходимое.
- Не использовать localStorage как основную базу.
